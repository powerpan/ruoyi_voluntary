# 分阶段任务拆解

## 1. 推进原则

本项目不采用一次性整体改造方式。每个阶段只处理一个清晰目标，完成后必须更新文档并进行验证。

基本原则：

1. 先文档，后代码。
2. 先工程骨架，后业务模块。
3. 先核心闭环，后扩展功能。
4. 每个阶段都要能说明完成了什么、没有做什么、如何验证。
5. 不把下一阶段的功能提前混入当前阶段。

### 5.4 验收场景

1. 新用户注册后状态为待审核。
2. 待审核用户登录后能查看和维护资料。
3. 用户端首页和个人中心能展示审核状态。
4. 管理员可以通过或驳回志愿者。
5. 审核通过后用户端状态变为已通过。
6. 驳回后用户能看到原因并修改资料。
7. 审核状态服务方法可供 P3 报名资格校验复用。
