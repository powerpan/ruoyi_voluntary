# P4-G 用户端页面记录

## 1. 本阶段目标

P4-G 的目标是在 P4-D 扫码接口和 P4-E 服务记录接口基础上，补齐志愿者端页面，使志愿者可以通过后台生成的扫码地址完成签到签退，并在用户端查看个人服务记录和累计服务时长。

本阶段只实现：

1. 用户端扫码结果页 `/scan?token=...`。
2. 用户端扫码入口 `/scan`，支持粘贴扫码地址或 token 进入结果页。
3. 用户端个人服务记录页 `/service-records`。
4. 用户端导航中增加“扫码签到”入口。
5. 用户端首页阶段文案同步到 P4。

本阶段不实现统计图表、通知中心、导出、证书、定位签到、动态二维码刷新或人工补签。

## 3. 页面功能

### 3.1 扫码结果页

访问路径：

```text
/scan?token=<token>
```

页面能力：

1. 根据 token 读取二维码类型、活动信息、报名状态和当前签到签退状态。
2. 签到 token 展示“确认签到”按钮。
3. 签退 token 展示“确认签退”按钮。
4. 不满足条件时展示后端返回的状态提示，并禁用操作按钮。
5. 签到成功后刷新状态，显示已签到和签到时间。
6. 签退成功后刷新状态，显示已签退和签退时间，并提供“查看服务记录”入口。

访问路径：

```text
/scan
```

页面能力：

1. 无 token 时展示扫码地址或令牌输入框。
2. 支持粘贴完整扫码地址，例如 `http://localhost:8088/#/scan?token=...`。
3. 支持只粘贴 token 字符串。
4. 识别 token 后跳转到 `/scan?token=<token>`。

### 3.2 服务记录页

访问路径：

```text
/service-records
```

页面能力：

1. 展示累计服务小时、服务分钟和有效服务次数。
2. 按活动名称、记录状态和服务日期范围筛选个人服务记录。
3. 展示活动名称、服务地点、服务日期、计入时间、服务分钟数、记录状态和来源签到记录 ID。
4. 支持分页。

## 4. 接口清单

| 方法 | 路径 | 页面用途 |
| --- | --- | --- |
| `GET` | `/app/voluntary/scan/{token}` | 扫码页读取活动、报名和当前操作状态 |
| `POST` | `/app/voluntary/scan/{token}/checkin` | 扫码页确认签到 |
| `POST` | `/app/voluntary/scan/{token}/checkout` | 扫码页确认签退 |
| `GET` | `/app/voluntary/service-records/mine` | 服务记录页读取个人记录列表 |
| `GET` | `/app/voluntary/service-records/summary` | 服务记录页读取累计时长和次数 |
