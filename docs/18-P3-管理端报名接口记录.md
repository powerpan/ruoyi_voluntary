## 1. 本次目标

本次推进范围是 P3-E：在活动发布、用户端报名接口已完成的基础上，补齐管理端报名列表、详情和筛选接口。

本次完成：

1. 管理端分页查询报名列表。
2. 管理端查询报名详情。
3. 管理员将报名筛选为通过、拒绝或候补。

本次不做管理端页面，不做用户端页面，也不提前实现二维码签到签退和服务时长统计。

## 3. 接口清单

接口前缀：`/manager/voluntary/signups`

| 方法 | 路径 | 功能 | 权限 |
| --- | --- | --- | --- |
| `GET` | `/list` | 报名分页列表 | `manager:voluntary:signup:list` |
| `GET` | `/{id}` | 报名详情 | `manager:voluntary:signup:query` |
| `PUT` | `/{id}/review` | 筛选报名 | `manager:voluntary:signup:review` |

筛选请求体：

```json
{
  "status": 1,
  "reviewReason": "符合活动要求"
}
```

`status` 取值：

| 值 | 说明 |
| --- | --- |
| `1` | 通过 |
| `2` | 拒绝 |
| `3` | 候补 |

## 4. 服务层规则

### 4.1 列表与详情

管理端报名列表复用 `VolActivitySignupMapper.selectVolActivitySignupList`，当前支持以下过滤条件：

1. 活动 ID。
2. 志愿者用户 ID。
3. 姓名、电话、组织。
4. 报名状态。
5. 活动标题。
6. 活动类型。
7. 报名创建时间范围。

报名列表会关联活动信息，返回活动标题、活动类型、服务地点、活动时间和活动状态，便于后续管理端页面直接展示。

### 4.2 筛选状态校验

管理员筛选报名时，服务层校验：

1. 报名 ID 不能为空。
2. 筛选状态不能为空。
3. 筛选状态只能为通过、拒绝或候补。
4. 报名记录必须存在。
5. 只有待筛选和候补状态允许筛选。
6. 已取消报名不能筛选。
7. 已通过报名不能重复筛选。
8. 已拒绝报名不能再次筛选。

### 4.3 招募人数上限

管理员将报名筛选为通过时，服务层会：

1. 查询对应活动。
2. 校验活动招募人数配置有效。
3. 统计当前已通过报名数量。
4. 若已通过人数达到 `recruit_count`，拒绝本次通过操作。
5. 筛选成功后将活动 `approved_count` 更新为通过后的数量。

当前 P3-E 不允许已通过报名再改为拒绝或候补，因此通过人数减少由 P3-D 已完成的“志愿者取消已通过报名”规则处理。
