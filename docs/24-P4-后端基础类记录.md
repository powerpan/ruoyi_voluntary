# P4-B 后端基础类记录

## 1. 本阶段目标

P4-B 的目标是为二维码签到签退与服务记录补齐后端基础层，只完成实体、Mapper、XML 和基础 Service，不提前实现接口、页面、扫码业务闭环或统计页面。

本阶段为后续 P4-C、P4-D、P4-E 提供以下能力：

1. 二维码令牌可以被创建、查询、停用和按 token 校验有效性。
2. 签到签退记录可以按活动、报名、志愿者和状态查询。
3. 服务记录可以按活动、志愿者、签到记录和状态查询。
4. 服务记录基础层可以汇总某志愿者有效服务分钟数和服务次数。

## 3. 能力边界

### 3.1 二维码令牌

已提供：

1. 按 ID 查询。
2. 按 token 查询。
3. 按 token 查询有效令牌，要求 `status = 0` 且未过期。
4. 条件列表查询。
5. 新增、更新、删除。
6. 按活动和操作类型停用有效 token。

暂不提供：

1. 生成随机 token 的管理端接口。
2. 二维码图片或扫码 URL 组装。
3. 动态二维码刷新。

### 3.2 签到签退记录

已提供：

1. 按 ID 查询。
2. 按活动和志愿者查询唯一签到记录。
3. 条件列表查询，包含活动标题、服务地点、志愿者姓名、电话等展示字段。
4. 当前用户自己的签到记录列表查询。
5. 新增、更新、删除。

暂不提供：

1. 扫码签到业务校验。
2. 扫码签退业务校验。
3. 异常补录接口。

### 3.3 服务记录

已提供：

1. 按 ID 查询。
2. 按签到记录 ID 查询。
3. 条件列表查询，包含活动和志愿者展示字段。
4. 当前用户自己的服务记录列表查询。
5. 汇总某志愿者有效服务分钟数。
6. 统计某志愿者有效服务次数。
7. 新增、更新、删除。

暂不提供：

1. 签退后自动生成服务记录。
2. 按活动最大可计入分钟数裁剪。
3. 更新志愿者档案累计时长。
4. 管理端服务记录接口和页面。

## 4. 校验规则

基础 Service 只做通用入参保护：

1. 新增二维码令牌时要求活动 ID、token、操作类型和过期时间不为空。
2. 二维码操作类型只允许 `checkin` 和 `checkout`。
3. 新增签到记录时要求活动 ID、报名 ID、志愿者用户 ID 不为空。
4. 新增服务记录时要求活动 ID、报名 ID、签到记录 ID、志愿者用户 ID、服务日期和服务时间不为空。
5. “我的签到记录”和“我的服务记录”必须传入当前用户 ID。

完整业务校验进入后续阶段：

1. P4-C：管理端生成、查询、停用二维码 token。
2. P4-D：用户端扫码签到、签退和资格校验。
3. P4-E：签退后生成服务记录、累计时长维护和服务记录接口。
