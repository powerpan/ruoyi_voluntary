# P4-E 服务记录接口记录

## 1. 本阶段目标

P4-E 的目标是在 P4-D 二维码签到签退基础上补齐服务记录生成和查询接口，使“签到 -> 签退 -> 有效服务记录 -> 个人时长汇总”形成后端闭环。

本阶段只实现：

1. 签退成功后自动生成服务记录。
2. 按签到签退时间计算服务分钟数。
3. 按活动 `max_service_minutes` 限制可计入分钟数。
4. 更新志愿者档案累计服务分钟数和服务次数。
5. 用户端查询我的服务记录和汇总。
6. 管理端查询服务记录列表和详情。

本阶段不实现页面、统计图表、通知中心、导出、人工修正或异常集中处理。

## 3. 接口清单

### 3.1 用户端我的服务记录

```http
GET /app/voluntary/service-records/mine
```

登录：需要。

支持分页参数和基础筛选参数：

| 参数 | 说明 |
| --- | --- |
| `pageNum` | 页码 |
| `pageSize` | 每页条数 |
| `activityId` | 活动 ID |
| `status` | 服务记录状态 |
| `beginTime` | 服务日期开始 |
| `endTime` | 服务日期结束 |

接口强制使用当前登录用户 ID 过滤，用户不能查询他人的服务记录。

### 3.2 用户端服务时长汇总

```http
GET /app/voluntary/service-records/summary
```

登录：需要。

返回字段：

| 字段 | 说明 |
| --- | --- |
| `volunteerUserId` | 当前志愿者用户 ID |
| `totalServiceMinutes` | 累计有效服务分钟数 |
| `serviceCount` | 有效服务次数 |

### 3.3 管理端服务记录列表

```http
GET /manager/voluntary/service-records/list
```

权限：

```text
manager:voluntary:serviceRecord:list
```

支持按活动、志愿者、状态、服务日期范围等条件查询。

### 3.4 管理端服务记录详情

```http
GET /manager/voluntary/service-records/{id}
```

权限：

```text
manager:voluntary:serviceRecord:query
```

## 4. 业务规则

### 4.1 生成服务记录

签退接口完成 `vol_checkin_record` 更新后，同一事务内调用服务记录生成逻辑。

生成前校验：

1. 签到记录必须存在。
2. 签到记录状态必须为 `1`，即已签退。
3. 签到时间和签退时间必须完整。
4. 活动必须存在。
5. 同一个 `checkin_record_id` 只能生成一条服务记录。

### 4.2 服务分钟数计算

计算规则：

```text
原始分钟数 = ceil((checkout_time - checkin_time) / 60000)
计入分钟数 = min(原始分钟数, activity.max_service_minutes)
```

规则说明：

1. 签退时间晚于签到时间时，最小计入 1 分钟，便于短时间接口冒烟也能验证累计值。
2. 活动未配置 `max_service_minutes` 或配置小于等于 0 时，不做上限裁剪。
3. 签退时间不晚于签到时间时，服务记录状态为异常，计入分钟数为 0。
4. 当前 P4-E 默认正常签退生成 `status=1` 的有效记录。

### 4.3 志愿者档案累计值

服务记录写入后，系统按当前志愿者所有有效服务记录重新汇总：

1. `vol_volunteer_profile.total_service_minutes`
2. `vol_volunteer_profile.service_count`

使用重新汇总而不是简单累加，避免后续人工修正、作废或重复请求导致累计值偏差。

### 5.2 接口冒烟结果

临时写入 2 条二维码 token：

| token | 类型 | 用途 |
| --- | --- | --- |
| `p4e_checkin_token` | `checkin` | 正常签到 |
| `p4e_checkout_token` | `checkout` | 正常签退并生成服务记录 |

验证结果：

| 场景 | 结果 |
| --- | --- |
| 正常签到 | 返回 `code=200`，生成 `vol_checkin_record(id=2, status=0)` |
| 签到后服务记录检查 | `vol_service_record` 数量仍为 `0` |
| 正常签退 | 返回 `code=200`，签到记录更新为 `status=1` |
| 签退后服务记录检查 | 生成 `vol_service_record(id=1, checkin_record_id=2, service_minutes=1, status=1)` |
| 档案累计值检查 | `total_service_minutes=1`，`service_count=1` |
| 用户端我的服务记录 | `GET /app/voluntary/service-records/mine` 返回 `total=1` |
| 用户端服务汇总 | `GET /app/voluntary/service-records/summary` 返回 `1 / 1` |
| 管理端服务记录列表 | `GET /manager/voluntary/service-records/list` 返回 `total=1` |
| 管理端服务记录详情 | `GET /manager/voluntary/service-records/1` 返回服务记录详情 |
| 重复签退 | 返回 `已完成签退，不能重复签退`，服务记录数量仍为 `1` |

关键数据库落点：

```text
vol_service_record:
id=1
activity_id=2
signup_id=2
checkin_record_id=2
volunteer_user_id=2
service_date=2026-05-25
start_time=2026-05-25 09:22:05
end_time=2026-05-25 09:22:19
service_minutes=1
status=1
create_by=p3g_demo_volunteer
remark=二维码签退自动生成服务记录

vol_volunteer_profile:
user_id=2
total_service_minutes=1
service_count=1
```

## 6. 测试数据清理

1. `vol_activity_qr_token` 中 2 条 `create_by=p4e_smoke` 的 token。

验证完成后清理临时 token、签到记录和服务记录，并将测试用户累计值恢复为当前有效服务记录汇总值。
