本次验收范围是 P4-H：确认“二维码签到签退与服务记录”阶段已经形成可运行闭环。

## 4. 接口验收

验收命令以真实登录 token 调用当前后端接口。为了验证有效服务时长，又不等待真实分钟流逝，在签到成功后将本次临时签到记录的 `checkin_time` 回拨 2 分钟，再执行真实二维码签退接口。

### 4.1 二维码生成

| 场景 | 结果 |
| --- | --- |
| 管理端生成签到二维码 | `code=200`，生成 `checkin_id=29` |
| 管理端生成签退二维码 | `code=200`，生成 `checkout_id=30` |
| 扫码地址格式 | `http://localhost:8088/#/scan?token=...` |

### 4.2 边界拦截

| 场景 | 结果 |
| --- | --- |
| 未登录访问扫码接口 | 返回 `code=401`，提示认证失败 |
| 未报名用户扫码 | 返回“未报名该活动，不能扫码签到签退” |
| 报名未通过用户扫码 | 返回“报名未通过，不能扫码签到签退” |
| 已通过报名但未签到就扫码签退 | 返回“尚未签到，不能签退” |
| 已签到后再次扫码签到 | 返回“已完成签到，不能重复签到” |
| 已签退后再次扫码签退 | 返回“已完成签退，不能重复签退” |

### 4.3 正常闭环

| 步骤 | 结果 |
| --- | --- |
| 已通过报名用户扫码签到 | 返回“可以签到”，执行签到后生成 `checkin_record_id=7` |
| 已签到用户扫码签退 | 返回“可以签退”，执行签退后签到记录状态为 `1` |
| 自动生成服务记录 | 用户端个人服务记录 `total=1` |
| 服务时长计算 | 本次服务记录 `serviceMinutes=2`，状态 `1` |
| 个人服务汇总 | 用户端汇总 `totalServiceMinutes=2`，`serviceCount=1` |
| 管理端签到记录查询 | `GET /manager/voluntary/checkins/list` 返回 `total=1` |
| 管理端服务记录查询 | `GET /manager/voluntary/service-records/list` 返回 `total=1` |

## 7. P4 验收结论

P4 已完成。当前已证明以下验收场景成立：

1. 管理员可以生成签到二维码和签退二维码。
2. 二维码内容为用户端扫码地址和随机 token，不暴露活动或用户业务字段。
3. 未登录用户不能调用扫码接口。
4. 未报名用户不能签到签退。
5. 报名未通过用户不能签到签退。
6. 已通过报名用户可以扫码签到。
7. 重复签到会被拦截。
8. 未签到不能签退。
9. 已签到用户可以扫码签退。
10. 重复签退会被拦截。
11. 签退成功后自动生成服务记录。
12. 有效服务记录会计入个人累计服务分钟数和服务次数。
13. 用户端可以查看个人服务记录和汇总。
14. 管理端可以查看签到签退记录和服务记录。
15. 验收临时数据已清理，必要演示数据仍保留。

P4 不再继续扩展统计图表、通知中心、导出、人工补签、异常集中处理或定位签到；这些内容进入 P5 或后续扩展。
