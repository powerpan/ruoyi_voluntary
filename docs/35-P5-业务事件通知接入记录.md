# P5-D 业务事件通知接入记录

## 1. 本次目标

本次推进范围是 P5-D：在 P5-C 已具备通知基础接口的基础上，把核心业务动作接入 `vol_notification`，使志愿者能够收到审核结果、报名筛选结果和服务记录变化通知。

本次只处理后端业务事件投递，不提前实现导出接口、统计页面、通知页面改造、短信邮件微信推送或手工群发。

## 3. 通知事件

### 3.1 志愿者审核通知

触发位置：`VolVolunteerProfileServiceImpl.updateAuditStatus`

触发时机：

1. 管理员审核通过志愿者档案。
2. 管理员驳回志愿者档案。
3. 管理员禁用志愿者档案。
4. 管理员重新启用志愿者档案。

通知字段：

| 字段 | 值 |
| --- | --- |
| `notice_type` | `volunteer_audit` |
| `target_type` | `volunteer` |
| `target_id` | 志愿者档案 ID |
| `receiver_user_id` | 志愿者用户 ID |
| `actor_user_id` | 管理员用户 ID |
| `action_url` | `/me` |

标题根据状态生成：审核通过、审核驳回、已禁用、已启用。通知内容包含审核结论和审核意见。

### 3.2 报名筛选通知

触发位置：`VolActivitySignupServiceImpl.reviewActivitySignup`

触发时机：

1. 管理员将报名筛选为通过。
2. 管理员将报名筛选为拒绝。
3. 管理员将报名筛选为候补。

通知字段：

| 字段 | 值 |
| --- | --- |
| `notice_type` | `signup_review` |
| `target_type` | `signup` |
| `target_id` | 报名记录 ID |
| `receiver_user_id` | 志愿者用户 ID |
| `actor_user_id` | 管理员用户 ID |
| `action_url` | `/signups` |

标题带活动名称，例如 `报名已通过：社区清洁`。通知内容提示筛选结果，并在存在筛选意见时附加意见。

### 3.3 服务记录通知

触发位置：`VolServiceRecordServiceImpl`

触发时机：

1. 二维码签退后自动生成服务记录。
2. 管理端人工新增服务记录。
3. 管理端修改服务记录状态，且状态发生变化。

通知字段：

| 服务记录状态 | `notice_type` | 标题 |
| --- | --- | --- |
| 有效 | `service_record` | 服务记录已生成 |
| 异常 | `checkin_abnormal` | 服务记录异常 |
| 作废 | `service_record` | 服务记录已作废 |

其他字段：

| 字段 | 值 |
| --- | --- |
| `target_type` | `service_record` |
| `target_id` | 服务记录 ID |
| `receiver_user_id` | 志愿者用户 ID |
| `action_url` | `/service-records` |

待确认状态不发送通知，避免尚未确认的记录提前打扰志愿者。

## 4. 边界说明

1. P5-D 只写入站内通知，不做短信、邮件、微信或 App 推送。
2. P5-D 不做通知页面接入，用户端 `/notifications` 真实页面放到 P5-G。
3. P5-D 不做导出接口，导出进入 P5-E。
4. 活动取消、下架、结束等 `activity_change` 通知本次暂不接入，后续可在活动变更流程扩展。
5. 通知跳转地址仍复用 P5-C 的安全校验，只允许用户端内部路由。
