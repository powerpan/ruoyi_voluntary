## 3. 接口清单

用户端接口前缀：`/app/voluntary`

| 方法 | 路径 | 功能 | 登录要求 |
| --- | --- | --- | --- |
| `GET` | `/activities` | 已发布活动分页列表 | 可匿名 |
| `GET` | `/activities/{id}` | 已发布活动详情 | 可匿名 |
| `POST` | `/activities/{id}/signups` | 报名活动 | 需要登录且志愿者审核通过 |
| `GET` | `/signups/mine` | 我的报名列表 | 需要登录 |
| `POST` | `/signups/{id}/cancel` | 取消我的报名 | 需要登录 |

报名请求体：

```json
{
  "applyReason": "报名理由",
  "experience": "相关经验"
}
```

## 4. 服务层规则

### 4.1 活动公开浏览

用户端活动列表和详情只返回已发布活动：

```text
vol_activity.status = 1
```

如果请求未发布、已下架、已结束或已取消活动详情，服务层返回“活动不存在或未发布”，避免用户端暴露管理端未公开数据。

### 4.2 报名资格校验

志愿者提交报名时，服务层校验：

1. 用户 ID 不能为空。
2. 必须存在志愿者档案。
3. 必须通过志愿者审核，即 `isVolunteerApproved(userId) = true`。
4. 活动必须存在且状态为已发布。
5. 活动必须配置报名开始和截止时间。
6. 当前时间必须处于报名时间范围内。

报名成功后，系统写入报名时的姓名、手机号和组织快照，避免后续个人资料变化影响报名记录。

### 4.3 重复报名处理

同一志愿者同一活动只能有一条报名记录。

| 已有报名状态 | 本次处理 |
| --- | --- |
| 待筛选 | 拒绝重复提交 |
| 通过 | 拒绝重复提交 |
| 候补 | 拒绝重复提交 |
| 拒绝 | 拒绝用户直接重新提交，提示联系管理员 |
| 取消 | 更新原报名记录为待筛选，允许重新报名 |

取消后重新报名通过 `resubmitCancelledSignup` 更新原记录，不插入重复行，继续满足数据库唯一约束。

### 4.4 取消报名处理

志愿者取消报名时，服务层校验：

1. 报名 ID 不能为空。
2. 报名记录必须存在。
3. 只能操作自己的报名记录。
4. 已取消报名重复取消时保持幂等返回。
5. 已拒绝报名不能取消。
6. 如果取消的是已通过报名，需要同步减少活动 `approved_count`，最低不低于 0。
