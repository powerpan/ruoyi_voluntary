# P2 用户端档案接口记录

## 1. 本次目标

本次推进范围是 P2-D：实现用户端志愿者档案查询和维护接口。

本次完成后，登录后的志愿者可以：

1. 查询自己的系统账号信息和志愿者档案。
2. 查看自己的审核状态、审核意见和是否已通过审核。
3. 修改自己的志愿者档案资料。
4. 在驳回状态下重新提交资料，并自动回到待审核状态。

本接口阶段不做用户端页面接入，也不做管理端审核页面。用户端个人中心页面已在后续 `docs/09-P2-用户端个人中心页面记录.md` 中完成接入和验证。

## 2. 新增接口

接口前缀：

```text
/app/voluntary/profile
```

| 方法 | 路径 | 功能 | 登录要求 |
| --- | --- | --- | --- |
| `GET` | `/app/voluntary/profile` | 查询我的志愿者档案 | 需要 |
| `PUT` | `/app/voluntary/profile` | 修改我的志愿者档案 | 需要 |
| `GET` | `/app/voluntary/profile/audit-status` | 查询我的审核状态 | 需要 |

新增 Controller：

```text
ruoyi-admin/src/main/java/com/ruoyi/web/controller/app/voluntary/VolAppProfileController.java
```

## 3. 业务规则

### 3.1 查询规则

1. 只能查询当前登录用户自己的档案。
2. 返回 `sys_user` 基础用户信息。
3. 返回 `vol_volunteer_profile` 志愿者档案。
4. 返回 `auditStatus` 和 `approved`，方便用户端首页、个人中心和后续报名按钮复用。
5. 若当前账号不存在志愿者档案，则返回业务错误，提示重新注册或联系管理员。

### 3.2 修改规则

用户可维护字段：

| 字段 | 说明 |
| --- | --- |
| `realName` | 真实姓名 |
| `gender` | 性别 |
| `idCard` | 证件号 |
| `phone` | 联系电话 |
| `organization` | 所属组织 |
| `majorOrClass` | 学院班级或社区分组 |
| `specialty` | 服务特长 |
| `emergencyContact` | 紧急联系人 |
| `emergencyPhone` | 紧急联系电话 |

限制：

1. 用户不能修改 `id`、`userId`、`auditStatus`、`totalServiceMinutes`、`serviceCount` 等系统字段。
2. 禁用状态不能修改资料。
3. 驳回状态下修改资料后，自动变为待审核。
4. 已审核通过后，如果修改真实姓名或证件号，自动变为待审核。
5. 状态由驳回或通过回到待审核时，会写入一条 `vol_audit_record` 记录。

### 4.2 运行级接口冒烟

验证环境：

| 服务 | 地址 |
| --- | --- |
| 后端 | `http://127.0.0.1:8080` |
| MySQL | `127.0.0.1:33306` |
| Redis | `127.0.0.1:6379` |

验证步骤：

1. 启动项目内临时 MySQL。
2. 导入 `sql/ruoyi_voluntary.sql`。
3. 启动后端 Jar，并覆盖数据源端口为 `33306`。
4. 注册测试用户 `p2profile1`。
5. 登录后携带 `Authorization: Bearer <token>` 访问档案接口。

验证结果：

| 场景 | 结果 |
| --- | --- |
| 未登录访问 `/app/voluntary/profile` | 返回 `401` |
| 登录后 `GET /app/voluntary/profile` | 返回用户信息、档案、`auditStatus=0`、`approved=false` |
| 登录后 `PUT /app/voluntary/profile` | 可更新实名资料、组织、联系方式、特长等字段 |
| `GET /app/voluntary/profile/audit-status` | 返回 `auditStatus=0`、`approved=false` |
| 人工将档案置为驳回后再次 `PUT` | 档案回到待审核，并新增审核记录 |

数据库验证：

