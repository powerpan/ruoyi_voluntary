# P5-C 通知后端接口记录

## 1. 本次目标

本次推进范围是 P5-C：在 P5-A 已落地 `vol_notification` 表和通知字典的基础上，只实现通知基础后端能力，不提前接入审核、报名、服务记录等业务事件通知，也不实现导出接口或前端页面。

具体目标：

1. 新增 `VolNotification` 实体、Mapper、XML 和 Service。
2. 新增用户端通知接口：我的通知、未读数、单条已读、全部已读。
3. 新增管理端通知记录查询接口。
4. 在 Service 层校验用户只能读取和修改自己的通知。
5. 基于当前库做运行级接口冒烟验证，验证后清理临时通知数据。

## 3. 接口清单

### 3.1 用户端接口

接口前缀：`/app/voluntary/notifications`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/mine` | 我的通知分页列表 |
| `GET` | `/unread-count` | 我的未读通知数 |
| `PUT` | `/{id}/read` | 标记我的单条通知为已读 |
| `PUT` | `/read-all` | 标记我的全部未读通知为已读 |

### 3.2 管理端接口

接口前缀：`/manager/voluntary/notifications`

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| `GET` | `/list` | 通知记录分页列表 | `manager:voluntary:notification:list` |
| `GET` | `/{id}` | 通知详情 | `manager:voluntary:notification:query` |

## 4. 安全与边界

1. 用户端 `/mine` 会强制覆盖查询条件中的 `receiverUserId` 为当前登录用户 ID。
2. 用户端单条已读先按 ID 查询通知，再校验 `receiver_user_id = currentUserId`，不能标记他人的通知。
3. 单条已读允许重复点击：已读状态再次标记仍返回成功。
4. 全部已读只更新当前用户的未读通知，即使当前没有未读也返回成功。
5. `action_url` 只允许用户端内部路由，必须以 `/` 开头，不能以 `//` 开头，也不能包含 `://`。
6. 管理端 P5-C 只查询通知记录，不提供新增、删除、手工群发或批量重发能力。

### 6.2 用户端我的通知

接口：

```text
GET /app/voluntary/notifications/mine?pageNum=1&pageSize=10&targetType=p5c_smoke
```

使用 `p3g_demo_volunteer` 登录后返回：

```text
code=200
total=1
id=1
receiverUserId=2
title=P5C_SMOKE_用户2未读
status=0
actionUrl=/notifications
```

结论：用户端列表只返回当前登录用户自己的通知，没有返回 `user_id=3` 的通知。

### 6.3 未读数量

接口：

```text
GET /app/voluntary/notifications/unread-count
```

初始返回：

```text
code=200
data=1
```

用户标记自己的通知已读后再次返回：

```text
code=200
data=0
```

### 6.4 权限隔离

接口：

```text
PUT /app/voluntary/notifications/2/read
```

`id=2` 属于 `user_id=3`。使用 `p3g_demo_volunteer` 登录后调用返回：

```text
code=500
msg=通知不存在或无权操作
```

数据库复查：

```text
id=1 receiver_user_id=2 status=1 read_time=2026-05-25 14:19:11
id=2 receiver_user_id=3 status=0 read_time=NULL
```

结论：用户不能标记他人的通知，自己的通知已读操作不影响他人通知。

### 6.5 单条已读与全部已读

接口：

```text
PUT /app/voluntary/notifications/1/read
PUT /app/voluntary/notifications/read-all
```

验证结果：

1. 单条已读返回 `code=200`。
2. 已读通知再次调用单条已读仍返回 `code=200`。
3. 当前无未读通知时调用全部已读返回 `code=200`，`data=0`。

### 6.6 管理端通知记录

接口：

```text
GET /manager/voluntary/notifications/list?pageNum=1&pageSize=10&targetType=p5c_smoke
GET /manager/voluntary/notifications/1
```

验证结果：

1. 管理端列表返回 `total=2`，能看到两个用户的通知记录和接收人账号。
2. 管理端详情返回 `code=200`，能查看通知标题、接收人、状态和阅读时间。
