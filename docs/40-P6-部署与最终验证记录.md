# P6 部署与最终验证记录

## 1. 文档目的

本文档用于收口 P6 的部署、构建、数据库、启动和演示验证工作，使项目交付时具备可复现的运行说明和最终验收依据。

P6 不再新增业务功能，主要处理以下内容：

1. 确认可编译、可构建、可启动。
2. 确认初始化 SQL、账号、端口和环境变量说明清楚。
3. 确认核心业务链路能被演示。
4. 明确演示截图和论文材料来源。
5. 记录验证命令、验证结果和已知环境限制。

## 2. 推荐环境

| 类别 | 推荐版本或说明 |
| --- | --- |
| JDK | 8 或兼容 Spring Boot 2.5 的 JDK |
| Maven | 3.6+ |
| Node.js | 14 或 16，Node 17+ 需要保留 `NODE_OPTIONS=--openssl-legacy-provider` |
| npm | 随 Node 安装即可 |
| MySQL | 5.7 或 8.0，字符集 `utf8mb4` |
| Redis | 5.0+ |
| 浏览器 | Chrome、Edge 或 Safari |
| 操作系统 | macOS、Windows 或 Linux 均可，本地脚本以 macOS 为主 |

说明：

1. 管理端和用户端均为 Vue 2 项目。
2. 后端使用 RuoYi-Vue 3.8.7 体系，启动模块是 `ruoyi-admin`。
3. 志愿业务代码集中在 `voluntary-system`。

## 3. 本地部署步骤

### 3.1 准备数据库

创建数据库并导入初始化脚本：

```bash
mysql -uroot -p < sql/ruoyi_voluntary.sql
```

如果只需要最小基础数据，可导入：

```bash
mysql -uroot -p < sql/ruoyi_voluntary_minimal.sql
```

两份脚本都会创建数据库：

```sql
CREATE DATABASE IF NOT EXISTS `ruoyi_voluntary`
```

脚本差异：

| 脚本 | 用途 |
| --- | --- |
| `sql/ruoyi_voluntary.sql` | 完整演示库，包含系统基础数据、志愿业务菜单、字典和演示数据 |
| `sql/ruoyi_voluntary_minimal.sql` | 最小初始化库，适合重新演示注册、审核和活动创建流程 |

### 3.2 准备 Redis

本地开发默认使用：

| 配置 | 默认值 |
| --- | --- |
| Host | `localhost` |
| Port | `6379` |
| Database | `6` |
| Password | 空 |

对应配置文件：

```text
ruoyi-admin/src/main/resources/application-dev.yml
```

### 3.3 后端配置

本地开发默认数据库配置：

| 配置 | 默认值 |
| --- | --- |
| 数据库 | `ruoyi_voluntary` |
| 地址 | `jdbc:mysql://localhost:3306/ruoyi_voluntary` |
| 用户名 | `root` |
| 密码 | `root` |

可通过环境变量覆盖：

```bash
export RUOYI_VOLUNTARY_DB_USER=root
export RUOYI_VOLUNTARY_DB_PASSWORD=root
```

### 3.4 启动三端服务

推荐使用根目录脚本：

```bash
./start-dev.command
```

脚本会启动：

| 服务 | 默认地址 |
| --- | --- |
| 后端 | `http://localhost:8080` |
| 管理端 | `http://localhost:8081` |
| 用户端 | `http://localhost:8088` |

停止服务：

```bash
./stop-dev.command
```

如果已有服务占用端口，脚本会跳过对应服务启动，不强行关闭。

### 3.5 手工启动命令

后端：

```bash
mvn -pl ruoyi-admin -am package -DskipTests
java -jar ruoyi-admin/target/ruoyi-admin.jar --spring.profiles.active=dev
```

管理端：

```bash
cd ruoyi-ui
npm install
npm run dev
```

用户端：

```bash
cd voluntary-app
npm install
npm run dev
```

## 6. 核心演示流程

### 6.1 志愿者注册与审核

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 用户端打开注册页 | 能填写账号、密码和基础信息 |
| 2 | 提交注册 | 系统创建账号和待审核档案 |
| 3 | 管理端进入“志愿管理 / 志愿者审核” | 能看到新注册志愿者 |
| 4 | 管理员审核通过 | 志愿者状态变为审核通过 |
| 5 | 志愿者进入个人中心 | 能看到审核通过状态 |

### 6.2 活动发布与报名筛选

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 管理端新增活动 | 活动保存为草稿 |
| 2 | 发布活动 | 用户端活动列表可见 |
| 3 | 志愿者查看详情并报名 | 报名记录状态为待筛选 |
| 4 | 管理端进入报名管理 | 能看到报名人员 |
| 5 | 管理员筛选通过 | 已通过人数更新，志愿者报名状态同步 |

### 6.3 二维码签到签退与服务时长

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 管理端为活动生成签到二维码 | 弹窗展示二维码和扫码链接 |
| 2 | 志愿者扫码签到 | 生成签到记录，状态为已签到 |
| 3 | 管理端为活动生成签退二维码 | 弹窗展示签退二维码和扫码链接 |
| 4 | 志愿者扫码签退 | 签到记录变为已签退 |
| 5 | 系统自动生成服务记录 | 服务分钟数计入志愿者累计时长 |

### 6.4 统计、通知与导出

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 管理端进入数据统计 | 能看到总览、活动统计、排行、组织统计和趋势 |
| 2 | 管理端进入通知记录 | 能查询志愿者审核、报名筛选和服务记录通知 |
| 3 | 用户端进入我的通知 | 只能看到当前用户自己的通知 |
| 4 | 管理端点击导出 | 志愿者、报名、签到、服务记录均能生成 Excel |

2. 前端生产构建命令。
3. 浏览器运行态页面检查。
4. SQL 文件结构检查和既有阶段导入记录。
5. 必要时由普通浏览器或 phpMyAdmin 做人工导入复核。

### 9.5 SQL 复核

当前 Codex 命令行环境可看到 MySQL 监听 `*:3306`，但新建到 `127.0.0.1:3306` 的 MySQL 客户端连接被沙箱拦截，因此本轮未在命令行中执行破坏性重导入。

本轮完成非破坏性 SQL 文件复核：

```text
sql/ruoyi_voluntary.sql          CREATE TABLE 数量：28
sql/ruoyi_voluntary_minimal.sql  CREATE TABLE 数量：28
完整脚本 manager:voluntary 权限标识数量：24
最小脚本 manager:voluntary 权限标识数量：24
完整脚本 vol_notification 相关定义数量：14
最小脚本 vol_notification 相关定义数量：14
```

说明：

1. 两份 SQL 在 P5-A 已通过完整导入和 minimal 导入验证。
2. 当前本地运行库也能支撑管理端统计、通知、用户端活动、个人中心和通知中心页面访问。
3. 演示前如需绝对干净环境，建议用普通终端或 phpMyAdmin 新建临时库后重新导入 `sql/ruoyi_voluntary.sql`。
