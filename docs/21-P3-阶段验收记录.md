# P3 阶段验收记录

## 1. 验收目标

本次验收范围是 P3-H：确认“活动与报名”阶段已经形成可运行闭环。

P3 收口后的能力包括：

1. 管理员可以创建活动草稿。
2. 管理员可以发布活动。
3. 游客可以浏览已发布活动列表和详情。
4. 审核通过的志愿者可以提交活动报名。
5. 志愿者可以查看自己的报名结果和管理员处理意见。
6. 管理员可以在报名管理中查看报名人员并执行筛选。
7. 报名筛选通过后，活动已通过人数会自动更新。
8. P3 只完成活动发布、浏览、报名和筛选，不进入二维码签到签退、服务记录和服务时长统计。

## 4. 接口验收

接口验证按真实业务顺序执行。

| 步骤 | 接口 | 验证结果 |
| --- | --- | --- |
| 1 | `POST /login` | 管理员登录成功，返回 `code=200` |
| 2 | `POST /manager/voluntary/activities` | 创建 `P3-H闭环验收活动` 成功，初始 `status=0` |
| 3 | `PUT /manager/voluntary/activities/2/status` | 发布成功，返回 `status=1` 和 `publishTime` |
| 4 | `GET /app/voluntary/activities` | 游客活动列表查询成功，`total=1`，活动状态为已发布 |
| 5 | `GET /app/voluntary/activities/2` | 游客活动详情查询成功，返回 `status=1` |
| 6 | `POST /login` | 志愿者登录成功，返回 `code=200` |
| 7 | `POST /app/voluntary/activities/2/signups` | 志愿者报名成功，初始 `status=0` 待筛选 |
| 8 | `GET /manager/voluntary/signups/list` | 管理端报名列表可查询到该报名，状态为待筛选 |
| 9 | `PUT /manager/voluntary/signups/2/review` | 管理员筛选通过成功，返回 `status=1` |
| 10 | `GET /manager/voluntary/activities/2` | 活动 `approvedCount=1`，与通过报名数一致 |
| 11 | `GET /app/voluntary/signups/mine` | 志愿者“我的报名”可看到通过状态和处理意见 |

## 7. P3 验收结论

P3 已完成。当前已证明以下验收场景成立：

1. 管理员可以创建、发布和查看活动。
2. 用户端只展示已发布活动。
3. 审核通过的志愿者可以报名活动。
4. 报名成功后初始状态为待筛选。
5. 管理员可以在报名管理中看到报名人员。
6. 管理员可以将报名筛选为通过。
7. 筛选通过后，活动已通过人数自动增加。
8. 志愿者可以在我的报名中看到筛选结果和处理意见。

P3 不再继续扩展二维码签到、签退、服务记录或服务时长统计；这些内容进入 P4 和 P5。
