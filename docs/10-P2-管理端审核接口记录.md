# P2 管理端审核接口记录

## 1. 本次目标

本次推进范围是 P2-E：实现管理端志愿者档案查询、维护、审核和状态管理接口。

本次完成后，管理员可以通过后端接口完成：

1. 按账号、姓名、手机号、组织和审核状态查询志愿者档案。
2. 查看志愿者档案详情。
3. 管理员维护志愿者档案资料。
4. 审核通过或驳回志愿者档案。
5. 禁用或启用志愿者档案。
6. 查看志愿者审核记录。

本次不做管理端页面，也不做活动报名权限拦截。

## 2. 新增接口

接口前缀：

```text
/manager/voluntary/volunteers
```

| 方法 | 路径 | 功能 | 权限标识 |
| --- | --- | --- | --- |
| `GET` | `/list` | 志愿者分页列表 | `manager:voluntary:volunteer:list` |
| `GET` | `/{id}` | 志愿者详情 | `manager:voluntary:volunteer:query` |
| `PUT` | `/{id}` | 管理员编辑档案 | `manager:voluntary:volunteer:edit` |
| `POST` | `/{id}/audit` | 通过或驳回 | `manager:voluntary:volunteer:audit` |
| `PUT` | `/{id}/status` | 禁用或启用 | `manager:voluntary:volunteer:edit` |
| `GET` | `/{id}/audit-records` | 查看审核记录 | `manager:voluntary:volunteer:query` |

新增 Controller：

```text
ruoyi-admin/src/main/java/com/ruoyi/web/controller/manager/voluntary/VolManagerVolunteerController.java
```

## 3. 后端改动

### 3.1 档案展示字段

`VolVolunteerProfile` 增加管理端展示字段：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `userName` | `sys_user.user_name` | 登录账号 |
| `nickName` | `sys_user.nick_name` | 用户昵称 |
| `email` | `sys_user.email` | 邮箱 |
| `userStatus` | `sys_user.status` | 账号启停状态 |

`VolVolunteerProfileMapper.xml` 的查询 SQL 已左连接 `sys_user`，方便管理端列表直接展示账号信息。

### 3.2 服务层方法

`IVolVolunteerProfileService` 增加：

| 方法 | 说明 |
| --- | --- |
| `updateVolunteerProfileByManager` | 管理员维护志愿者档案资料 |
| `auditVolunteerProfile` | 审核通过或驳回 |
| `changeVolunteerProfileStatus` | 禁用或启用 |
| `selectVolunteerAuditRecords` | 查询某个志愿者档案的审核记录 |

状态流转和审核记录统一在 `VolVolunteerProfileServiceImpl` 中处理，避免 Controller 直接操作数据库状态。

## 4. 业务规则

### 4.1 审核接口

`POST /manager/voluntary/volunteers/{id}/audit`

请求字段：

| 字段 | 说明 |
| --- | --- |
| `auditStatus` | `1` 通过，`2` 驳回 |
| `auditReason` | 审核意见 |

规则：

1. 只允许传入 `1` 或 `2`。
2. 驳回时必须填写 `auditReason`。
3. 通过时如未填写意见，默认记录“管理员审核通过”。
4. 每次真实状态变化都会写入 `vol_audit_record`。

### 4.2 状态接口

`PUT /manager/voluntary/volunteers/{id}/status`

请求字段：

| 字段 | 说明 |
| --- | --- |
| `auditStatus` | `1` 启用，`3` 禁用 |
| `auditReason` | 状态变更原因 |

规则：

1. 只允许传入 `1` 或 `3`。
2. 禁用时用户端不可再修改档案。
3. 启用时状态恢复为通过。
4. 每次真实状态变化都会写入 `vol_audit_record`。

### 5.2 运行级接口验证

验证环境：

| 服务 | 地址 |
| --- | --- |
| 后端 | `http://127.0.0.1:8080` |
| MySQL | `127.0.0.1:33306` |
| Redis | `127.0.0.1:6379` |

验证步骤：

1. 启动项目内临时 MySQL。
2. 导入 `sql/ruoyi_voluntary.sql`。
3. 启动后端 Jar，并覆盖数据源端口为 `33306`。
4. 使用 `admin/admin123` 登录获取管理端 token。
5. 注册测试志愿者 `p2audit001`。
6. 调用管理端列表、编辑、审核、禁用、启用、驳回和审核记录接口。

验证结果：

| 场景 | 结果 |
| --- | --- |
| 志愿者注册 | 创建 `sys_user`、`vol_volunteer_profile` 和初始审核记录 |
| `GET /list?userName=p2audit001` | 返回 1 条记录，包含 `userName`、`nickName`、`auditStatus=0` |
| `PUT /{id}` | 管理员可维护实名资料、手机号、组织等字段 |
| `POST /{id}/audit` 通过 | `auditStatus` 变为 `1`，写入审核记录 |
| `PUT /{id}/status` 禁用 | `auditStatus` 变为 `3`，写入审核记录 |
| `PUT /{id}/status` 启用 | `auditStatus` 变为 `1`，写入审核记录 |
| `POST /{id}/audit` 驳回 | `auditStatus` 变为 `2`，写入审核记录 |
| 驳回不填原因 | 返回 `code=500`，消息为“驳回时必须填写审核意见” |
| `GET /{id}/audit-records` | 返回注册、通过、禁用、启用、驳回共 5 条记录 |

数据库验证：

```text
audit_status  audit_reason  auditor_name  audit_record_count
2             联调驳回测试  admin         5
```
